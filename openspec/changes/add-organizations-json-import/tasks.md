> reuses its import page, `ImportRun`, `ImportFileStorage`, the review table,

## 1. JSON Schema as the single source of truth

- [x] 1.1 Write `resources/import/organization-import.schema.json`: a draft 2019-09 schema with a required `organizations` array of `minItems: 1` and the fields `name` (required, minLength 1, maxLength 255), `industry` (maxLength 255), `city` (maxLength 255), `website` (maxLength 255), `description`, `coursesAttended` (maxLength 255), `unp` (maxLength 32), `annualPlan` (maxLength 255), `contacts[]` (`name` required + minLength 1, `position`, `phone` maxLength 32, `email`, `isMain` boolean), `calls[]` (`date`, `notes`), `nextCall` (`date`, `purpose`). It SHALL contain no `format` keyword. Every property SHALL carry a description that names its own constraint. `unp`, `annualPlan` and `isMain` are declared and none of them is required — a reversal of this task's first wording, taken by design D2: a payload from another source carries them for real, and refusing such an answer wholesale refuses the plain list of organizations the format is also for; "do not invent" stays in the prompt, where it belongs. Draft 2019-09, not 2020-12: `justinrainbow/json-schema` 6.x ships constraint classes only up to draft2019, so `$defs` from 2020-12 не разрешается — схема объявляет `definitions` и валидируется той версией библиотеки, что закреплена в lock-файле. Verify: a test asserts the fields are declared with their limits, that `additionalProperties` is `false`, that no `format` keyword is used, and that every property has a description mentioning its maximum length or requiredness.
- [x] 1.2 Declare a `pattern` on `calls[].date` and `nextCall.date` matching the date shapes of «Формат CSV-файла» (`D.M.YYYY`, `DD.MM.YYYY`, `DD.MM.YY`, `DD/MM/YYYY`, `DD,MM.YYYY`, optional trailing `_` or `.`), without the CSV entry parentheses. Add a test that feeds every date the schema accepts through `InteractionDateParser::parseDate()` and asserts none returns null, and that `31.08`, `09.04.202`, `09.04.20255` are rejected by the schema. Verify: both directions green.
- [x] 1.3 Promote `justinrainbow/json-schema` from a transitive **dev-only** dependency (`packages-dev`, required by `php-cs-fixer` and `infection`) to a direct requirement in `composer.json`, and regenerate `composer.lock` so the package leaves `packages-dev`. Verify: `composer validate` passes, the package has left `packages-dev` in `composer.lock`, and it is present under `require`.
- [x] 1.4 Create `ImportJsonSchema` service: `path()`, `raw(): array`, `fieldDictionary(): array` (property name → description, resolved through `$ref`), `nestedFieldDictionary(): array` for `contact` / `call` / `nextCall`, `decode(string): mixed`, `validate(mixed): JsonValidationResult`, `validateText(string): JsonValidationResult`, `organizationCount(mixed): int`, `prompt(): string`. The payload is decoded into objects, not assoc arrays: the validator tells a JSON object from an array apart, and a PHP array would fail `type: object` for every organization. The result SHALL list every violation as `{organizationIndex, field, message}`. Verify: test — a payload with an empty `name` at index 4 and a 40-character `phone` at index 6 reports both with the correct indices.
- [x] 1.5 Render the JSON tab prompt from `fieldDictionary()` and `nestedFieldDictionary()` so the prompt, the downloadable schema and the validator cannot drift, and so the model is told the date shapes, the maximum lengths and the required fields before it writes. The date shapes live in the descriptions of `call.date` and `nextCall.date`, so without the nested dictionaries the prompt would name no formats at all. The prompt is phrased as a general "разбери список организаций" task rather than "разбери выгрузку CRM", states that only `name` is required, and tells the model not to invent `unp` or `annualPlan`. Verify: a test asserts each schema description appears in the rendered prompt, that the two date `pattern`s are equal, that the example in the prompt contains no empty string, and that an answer of names only passes validation.

## 5. LLM client (browser-side)

> Раннера JS-тестов в репозитории нет: `package.json` знает только `dev`,
> `watch` и `build`, а `tests/` и `e2e/` — PHP и Playwright. Поэтому пункты
> этого раздела проверяются **чтением `assets/js/llm-client.js` и ручной
> проверкой в браузере**, а не автотестом; формулировка «Verify» ниже называет
> способ проверки прямо, чтобы задача не обещала теста, которого не будет.
> Всё, что проверяется на сервере (разметка вкладки, проекция схемы, 403),
> покрыто `ImportJsonControllerTest`.

- [x] 5.1 Implement the OpenAI-compatible browser client in `assets/js/llm-client.js`: `{ baseUrl, apiKey, model, headers }`, `listModels()`, `send(messages, schema)`, plus a `SessionKey` holder. Used by both providers, registered in `assets/app.js`. A `TypeError` from `fetch` is reported as a request the browser refused to issue, because that is what a blocked request looks like in practice. Verify: by reading the client — no request in it targets an application route, the only outbound calls are to the provider.
- [x] 5.2 Provider presets, each called its own way: OpenRouter (`POST https://openrouter.ai/api/v1/chat/completions`, `Authorization: Bearer`, `HTTP-Referer`, `X-OpenRouter-Title`, models at `GET /api/v1/models`, answer at `choices[0].message.content`) and Ollama (`POST <host>/api/chat`, no auth, `format` = schema, `stream: false`, `temperature: 0`, models at `GET /api/tags`, answer at `message.content`). An empty Ollama host means `http://localhost:11434`. Verify: by reading the presets — each issues the documented request shape and reads the answer from the documented path.
- [x] 5.3 Send the rendered prompt together with the administrator's source text and the published JSON Schema as the response format, showing a successful response on the page and offering it for download as `import-<дата>-<время>.json` — Latin letters and digits only, because a browser drops a non-ASCII name and saves the file as `download`. Nothing is submitted and no tab is switched to. A provider that rejects the format surfaces an error in the tab and leaves the import untouched. Verify: manually in the browser against a reachable provider — the response appears on the page, the download carries the same text under that name, no import run is created, and a rejection surfaces an error.
- [x] 5.4 Hold the key in a JavaScript variable backed by `sessionStorage`; never use `localStorage`, never send it to the application. The key field carries no `name`, so a form submitted without the script loaded cannot put it into a request to the application either. «Забыть ключ» удалён: ключ исчезает с вкладкой, а отдельное действие означало бы то же самое. Предупреждение о видимости ключа — короткая строка под полем, а не плашка внизу страницы. Verify: by reading the client — `sessionStorage` is the only storage it touches, and the key field has no `name`; the warning text itself is asserted by `ImportJsonControllerTest`.
