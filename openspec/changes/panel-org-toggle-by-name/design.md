## Context

Текущая реализация использует нативный HTML `<details>/<summary>` для раскрытия контактов и звонков организации. Summary элемент с текстом «Звонки и контакты организации» находится внутри второй строки таблицы (`<tr class="org-details">`).

Новый подход: вся строка организации становится кликабельной областью для раскрытия/сворачивания секции контактов и звонков. Вторая строка (`<tr class="org-details">`) скрыта по умолчанию через CSS и показывается только когда строка организации имеет класс `--expanded`. Внутренний элемент — `<div>` (не `<details>`), так как раскрытие управляется внешним триггером.

## Goals / Non-Goals

**Goals:**
- Убрать визуальный шум отдельной ссылки-раскрытия
- Сделать взаимодействие более прямым и интуитивным (клик по всей строке)
- Сохранить всю существующую функциональность раскрытия контактов и звонков
- Сохранить функциональность кнопки «Изменить» (она не должна раскрывать строку)
- Сохранить переход на страницу редактирования по клику на имя организации

**Non-Goals:**
- Изменение структуры данных или backend логики
- Изменение функциональности модального окна редактирования организации
- Изменение стилей карточек контактов или строк звонков

## Decisions

**1. Вся строка как кликабельная область**

Вместо замены ссылки на кнопку, вся строка организации (`<tr class="org-table__row">`) получает data-атрибут и становится кликабельной областью через JavaScript.

_Обоснование_: Более интуитивно — пользователь кликает по строке, чтобы раскрыть её содержимое. Это стандартный паттерн для таблиц с раскрываемыми строками.

_Альтернативы_: Сделать только название кликабельным — отвергнуто, так как пользователь может кликнуть в любую часть строки, и это должно работать.

**2. Исключение интерактивных элементов**

Обработчик клика по строке проверяет, был ли клик по интерактивному элементу. Если да — событие не обрабатывается, и элемент выполняет своё действие. Исключаются два типа элементов:

1. **Кнопка «Изменить»** (`[data-organization-edit]`) — открывает модальное окно редактирования.
2. **Ссылка на имя организации** (`.org-table__name-link` или `a` внутри ячейки имени) — выполняет переход на страницу редактирования организации.

_Обоснование_: Кнопка «Изменить» и ссылка имени имеют собственные действия, которые не должны конфликтовать с раскрытием строки. Пользователь ожидает, что клик по имени приведёт к переходу, а не к раскрытию деталей.

_Реализация_: Обработчик проверяет `event.target.closest('[data-organization-edit], .org-table__name-link')` — если клик был по любому из этих элементов или их потомкам, обработчик возвращает early.

**3. CSS для скрытия/показа секции + JS дляtoggleClass**

Вторая строка (`<tr class="org-details">`) скрыта по умолчанию через `display: none`. При наличии класса `org-table__row--expanded` у предыдущей строки (`<tr class="org-table__row">`) секция показывается через `display: table-row` (CSS adjacent sibling selector). Внутренний элемент — `<div class="org-details__box">` (не `<details>`), так как раскрытие управляется внешним CSS-триггером. JS-обработчик просто переключает класс `org-table__row--expanded` на строке организации.

_Обоснование_: Нативный `<details>` добавлял собственный disclosure triangle и текст «Details», которые конфликтовали с поведением. CSS-подход чище и не требует управления атрибутами на внутреннем элементе.

**4. Визуальная индикация кликабельности**

Строка организации получает `cursor: pointer` для индикации кликабельности. Название организации получает индикатор раскрытия (треугольник ▸) через `::before`. Класс `.org-table__row--expanded` добавляется к строке при раскрытии для управления поворотом индикатора.

_Обоснование_: Пользователь должен видеть, что строка кликабельна, и видеть состояние раскрытия.

**5. Идентификация через `data-org-row-toggle`**

Строка использует `data-org-row-toggle="{orgId}"`. JS переключает класс `--expanded` на этой же строке. CSS-селектор `.org-table__row--expanded + .org-details` управляет видимостью секции.

_Обоснование_: Простая и надёжная связь через CSS sibling selector, без навигации по DOM.

**6. Автоматическое раскрытие при highlight**

При наличии параметра `highlight` в URL строка организации не только подсвечивается, но и автоматически раскрывается.

**Серверная часть (Twig)**: При рендере шаблона, если `highlight == organization.id`, строка получает класс `org-table__row--expanded`. CSS-селектор `.org-table__row--expanded + .org-details` показывает секцию.

_Обоснование_: Пользователь, создавший контакт или звонок, должен сразу видеть результат своего действия без дополнительного клика для раскрытия строки.

## Risks / Trade-offs

**[Риск] Поломка существующих E2E тестов** → Все тесты, кликающие по `summary.org-details__summary`, обновляются на клик по строке организации `[data-org-row-toggle]`.

**[Риск] Конфликт с интерактивными элементами** → Обработчик клика по строке проверяет `event.target.closest('[data-organization-edit], .org-table__name-link')` и возвращает early, если клик был по кнопке «Изменить» или ссылке имени.

**[Риск] Случайные клики** → Пользователь может случайно кликнуть по строке, пытаясь выделить текст. → Mitigation: `cursor: pointer` явно показывает, что строка кликабельна. Выделение текста всё ещё работает (можно выделить текст в ячейках).
