## Why

Тело рассылки вводится в plain `<textarea>`, а письмо уходит голым HTML-фрагментом без email-документа, инлайн-стилей и текстовой части — вёрстка ломается в почтовых клиентах, а авторы не могут вставить картинку или таблицу. Нужен визуальный редактор, честная email-вёрстка и предпросмотр письма до запуска.

## What Changes

- **BREAKING** Поле `body` кампании переходит с plain text на HTML. Миграции данных нет: существующие данные пересоздаются, фикстуры переписываются на HTML-тела.
- Форма создания/редактирования кампании получает WYSIWYG-редактор **TipTap 2** (MIT) вместо `<textarea>`: панель форматирования (жирный, курсив, подчёркивание, зачёркивание, заголовки, списки, ссылка, цвет, выравнивание), вставка изображения по URL и **режим исходного HTML**. Настоящим полем формы остаётся `<textarea name="body">`: в визуальном режиме она скрыта и синхронизируется из редактора при отправке/переключении.
- Санитизация HTML при сохранении: `symfony/html-sanitizer` + собственный санитайзер атрибута `style` с allowlist CSS-свойств. Лимит тела — 200 000 символов; тело, из которого после санитизации не осталось допустимого содержимого, — ошибка валидации.
- Изображения — **только внешний https URL** (кнопка + диалог URL/alt/ширина). Загрузка, хранение, раздача файлов и CID-встраивание не входят в объём.
- Таблицы вставляются через режим исходного HTML. Table-расширения редактора регистрируются только чтобы таблицы переживали переход «исходник ↔ визуальный режим»; табличного UI (вставка/удаление строк и столбцов) нет.
- Новый **`CampaignEmailRenderer`** — единственный источник правды о том, как выглядит письмо: HTML-документ с шеллом 600px (doctype, табличная раскладка, прехедер, футер), инлайн CSS через `twig/cssinliner-extra` и автоматическая текстовая часть. Используется и отправкой, и всеми предпросмотрами.
- Существующие токены (`{{greeting}}`, `{{contact_name}}`, `{{organization_name}}`, `{{unsubscribe_url}}`) продолжают работать; значения в HTML-контексте экранируются.
- Три предпросмотра письма с **фиксированными демо-значениями токенов**: страница `GET /campaigns/{id}/preview`, модальное окно на карточке кампании (тот же документ в sandbox-iframe) и живое превью в форме (`POST /campaigns/preview` без записи в БД).
- Страница просмотра кампании рендерит HTML тела вместо `<pre>` с plain text.
- e2e-тесты заполняют тело через режим исходного HTML; фикстуры и тесты обновляются.

## Capabilities

### New Capabilities

- (нет)

### Modified Capabilities

- `campaigns`: тело письма становится HTML (WYSIWYG-редактор + санитизация); письмо формируется единым email-шаблоном с текстовой частью; добавляются предпросмотры письма; изменяются требования «Создание рассылки», «Генерация письма по шаблону» и «Отправка писем (фоновая обработка, MailingService)».

## Impact

- `templates/campaign/form.html.twig` — редактор, панель форматирования, переключатель режима, подсказка токенов, кнопка предпросмотра
- `templates/campaign/show.html.twig` — рендер HTML вместо `<pre>`, модалка предпросмотра
- `templates/emails/campaign.html.twig` (новый) — email-шелл; страница предпросмотра отдаёт этот же документ без отдельного шаблона
- `src/Controller/CampaignController.php` — санитизация при сохранении, маршруты предпросмотра
- `src/Service/MailingService.php` — сборка `Email` с html()/text() через `CampaignEmailRenderer`
- `src/Entity/Campaign.php` — методы подстановки токенов выносятся/рефакторятся
- Новые сервисы: `CampaignBodySanitizer`, `CampaignTokenFiller`, `CampaignEmailRenderer`, `CampaignStyleAttributeSanitizer`
- `config/packages/html_sanitizer.yaml` (новый)
- `assets/js/campaign-editor.js`, `assets/js/campaign-preview-modal.js` (новые), `assets/app.js`, `assets/scss/pages/campaigns.scss`
- `package.json` — пакеты TipTap 2; `composer.json` — `symfony/html-sanitizer`, `twig/cssinliner-extra`
- `src/DataFixtures/`, `tests/`, `e2e/tests/` — фикстуры и тесты
- Миграция Doctrine не требуется: колонка `campaign.body` уже `LONGTEXT`
- Архитектурное решение фиксируется в ADR-0014
