## Why

Вход в систему осуществляется по email, но для B2B CRM удобнее вход по имени пользователя (login/никнейм) — email может меняться, а login остаётся постоянным идентификатором. Текущая реализация использует `property: email` в security.yaml и `getUserIdentifier()` возвращает email.

## What Changes

- **User**: добавляется поле `login` (string, unique, not null) — логин для входа
- **User**: поле `email` становится nullable (необязательным)
- **User**: поля `name` и `surname` располагаются после `email`
- **Security.yaml**: заменить `property: email` на `property: login` в provider
- **User::getUserIdentifier()**: изменить возврат с `$this->email` на `$this->login`
- **Форма входа**: переименовать поле «Email» → «Логин», изменить type с email на text
- **Форма установки пароля (Новый пользователь)**: заменить поле email на логин (login)
- **Сообщения об ошибках**: «Неверный email или пароль» → «Неверный логин или пароль»
- **Форма создания пользователя/менеджера**: добавить поле «Логин» (обязательное), email становится необязательным
- **Список пользователей (admin/users)**: «Логин» — первое поле в таблице
- **Профиль пользователя (header)**: отображение логина первым, затем имя/фамилия (если указаны), затем email (если указан)
- **Email остаётся**: email продолжает храниться и использоваться для писем/коммуникаций, но не для аутентификации
- **Миграция**: для существующих пользователей login = email (или name.surname), с возможностью ручного изменения

## Capabilities

### New Capabilities

Нет новых возможностей.

### Modified Capabilities

- `authentication` — замена поля аутентификации с email на login; форма входа

## Impact

- **Сущность User**: миграция — новое поле `login` (unique, not null, min=5), `email` становится nullable, `name` и `surname` после `email`
- **Security.yaml**: замена provider property
- **LoginController/login.html.twig**: обновить подписи, форма установки пароля по логину
- **Форма создания пользователя**: добавить поле «Логин» (обязательное, min=5), email необязательное
- **Список пользователей**: «Логин» — первое поле в таблице
- **Профиль пользователя (header)**: логин первым, имя/фамилия вторым, email третьим
- **Существующие пользователи**: миграция данных — `login = email` (или name.surname)
- **Обновить фикстуры**: добавить login для тестовых пользователей
