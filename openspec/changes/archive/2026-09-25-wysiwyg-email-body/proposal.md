## Why

Тело рассылки вводится в plain `<textarea>`, а письмо уходит голым HTML-фрагментом без email-документа, инлайн-стилей и текстовой части — вёрстка ломается в почтовых клиентах, а авторы не могут вставить картинку или таблицу. Нужен визуальный редактор, честная email-вёрстка и предпросмотр письма до запуска. Публичные страницы отписки дополнительно наследуют внутренний layout CRM и раскрывают навигацию приложения, хотя доступны получателям из интернета.

## What Changes

- **BREAKING** Поле `body` кампании переходит с plain text на HTML. Миграции данных нет: данные кампаний пересоздаются во всех средах, включая production, до выкладки; фикстуры переписываются на HTML-тела.
- Санитизация и редактор используют один email-safe контракт: разрешены H1–H6 (кнопки H1–H3 в тулбаре), списки, форматирование, стили на элементах и марках, inline `code`, изображение по внешнему https URL с `alt`, `title`, шириной и высотой, ссылки с `href`/`target`/`rel`, стилизованный `div` и стилизованная таблица с одним каноническим `tbody`, `colspan` и `rowspan`. `pre`/code-block, `thead`, `tfoot` и устаревшие presentation-атрибуты таблиц не поддерживаются. Round-trip гарантирует каноническое сохранение содержимого, а не побайтовую или буквальную CSS-нормализацию исходного кода.
- Токены рассылки запрещены в значениях CSS: объявление с `{{...}}` удаляется, остальные объявления того же `style` сохраняются.
- Форма создания/редактирования кампании получает WYSIWYG-редактор **TipTap 2** (MIT) вместо `<textarea>`: панель форматирования (жирный, курсив, подчёркивание, зачёркивание, заголовки H1–H3, списки, ссылка, цвет, выравнивание), вставка изображения по URL и **режим исходного HTML**. Настоящим полем формы остаётся `<textarea name="body">`: в визуальном режиме она скрыта и синхронизируется из редактора при отправке/переключении.
- Санитизация HTML при сохранении: `symfony/html-sanitizer` + собственный санитайзер атрибута `style` с allowlist CSS-свойств. Лимит тела — 200 000 символов; тело, из которого после санитизации не осталось допустимого содержимого, — ошибка валидации.
- Изображения — **только внешний https URL** (кнопка + диалог URL/alt/ширина). Загрузка, хранение, раздача файлов и CID-встраивание не входят в объём.
- Таблицы вставляются через режим исходного HTML. Table-расширения редактора регистрируются только чтобы таблицы переживали переход «исходник ↔ визуальный режим»; табличного UI (вставка/удаление строк и столбцов) нет.
- Новый **`CampaignEmailRenderer`** — единственный источник правды о том, как выглядит письмо: HTML-документ с шеллом 600px (doctype, табличная раскладка, прехедер, футер), инлайн CSS через `twig/cssinliner-extra` и автоматическая текстовая часть. Используется и отправкой, и всеми предпросмотрами.
- Существующие токены (`{{greeting}}`, `{{contact_name}}`, `{{organization_name}}`, `{{unsubscribe_url}}`) продолжают работать в теме, прехедере и теле; значения в HTML-контекстах экранируются ровно один раз.
- Публичная отписка рендерится в один из двух самостоятельных HTML-документов по состоянию: «Вы отписались от рассылки» после первого перехода или «Вы уже отписались» при повторном. Оба документа содержат только заголовок и поясняющий текст своего результата, не содержат внутренней навигации, внешних ассетов и ссылок на приложение и помечены `noindex, nofollow`.
- `max_input_length` санитайзера остаётся `262144` байт: несоответствие с лимитом в 200 000 символов для multibyte-текста выносится в отдельное серверное изменение до production-выкладки и не меняется в конфигурации приложения в рамках этого change.
- Три предпросмотра письма с **фиксированными демо-значениями токенов**: страница `GET /campaigns/{id}/preview`, модальное окно на карточке кампании (тот же документ в sandbox-iframe) и живое превью в форме (`POST /campaigns/preview` без записи в БД).
- Страница просмотра кампании рендерит HTML тела вместо `<pre>` с plain text.
- e2e-тесты заполняют тело через режим исходного HTML; фикстуры и тесты обновляются.

### Modified Capabilities

- `campaigns`: тело письма становится HTML (WYSIWYG-редактор + санитизация); письмо формируется единым email-шаблоном с текстовой частью; добавляются предпросмотры письма и standalone-страницы обоих результатов отписки; изменяются требования «Создание рассылки», «Генерация письма по шаблону» и «Отправка писем (фоновая обработка, MailingService)».

- `templates/campaign/form.html.twig` — редактор, панель форматирования, переключатель режима, подсказка токенов, кнопка предпросмотра
- `templates/campaign/show.html.twig` — рендер HTML вместо `<pre>`, модалка предпросмотра
- `templates/campaign/_preview_modal.html.twig` (новый) — общий sandbox-iframe для карточки и формы

- `src/Service/MailingService.php` — сборка `Email` с html()/text() через `CampaignEmailRenderer`
- `src/Entity/Campaign.php` — методы подстановки токенов выносятся/рефакторятся
- Новые сервисы: `CampaignBodySanitizer`, `CampaignTokenFiller`, `CampaignEmailRenderer`, `CampaignStyleAttributeSanitizer`; новый value object `RenderedEmail`
- `config/packages/html_sanitizer.yaml` (новый)
- `assets/js/campaign-editor.js`, `assets/js/campaign-preview-modal.js` (новые), `assets/app.js`, `assets/scss/pages/campaigns.scss`

- `src/DataFixtures/`, `tests/`, `e2e/tests/`, `e2e/helpers/` — фикстуры, функциональные и e2e-тесты, изоляция данных прогонов
