# ADR-0013: Статический анализ, код-стиль и мутационное тестирование

- **Status:** accepted
- **Date:** 2026-09-12

## Context

Проект не имеет автоматизированных инструментов контроля качества кода.
Качество обеспечивается только code review и ручной проверкой. Отсутствуют:
автоматическое обнаружение ошибок типизации, единый стандарт форматирования
и проверка покрытия тестами на логическом уровне. Это приводит к
 регрессиям, непоследовательности стиля и «мертвым» тестам, которые
не ловят реальные ошибки.

## Decision

Вводятся три инструмента, работающие как gatekeeper в CI:

1. **PHPStan** (статический анализ типов) — уровень 5 при запуске,逐步
   повышение до 8. Расширения: `phpstan-symfony`, `phpstan-doctrine`.
   Baseline для legacy-кода (`phpstan-baseline.neon`). Конфиг:
   `phpstan.neon`.

2. **PHP-CS-Fixer** (форматирование кода) — стандарт PER-CS 2.0, risky
   rules включены. Авто-fix локально (`cs`), проверка в CI (`cs-dry`).
   Конфиг: `.php-cs-fixer.dist.php`.

3. **Infection** (мутационное тестирование) — MSI ≥ 70%. Показывает,
   покрывают ли тесты реальную логику, а не просто «строчки кода».
   Интеграция с PHPStan для отсеивания ложных мутаций. Конфиг:
   `infection.json5`.

### Composer scripts

| Script | Команда | Назначение |
|---|---|---|
| `stan` | `phpstan analyse --no-progress` | Запуск анализа |
| `stan:baseline` | `phpstan analyse --generate-baseline` | Обновление baseline |
| `cs` | `php-cs-fixer fix --diff` | Авто-fix стиля |
| `cs:check` | `php-cs-fixer fix --dry-run --diff` | Проверка стиля |
| `infection` | `infection --threads=max --no-progress` | Мутационное тестирование |
| `quality` | `cs:check && stan && infection` | Все проверки |

### Makefile targets

| Target | Команда | Назначение |
|---|---|---|
| `make stan` | PHPStan анализ | Обнаружение ошибок типов |
| `make stan-baseline` | Генерация baseline | Обновление baseline |
| `make cs` | Авто-fix стиля | Форматирование кода |
| `make cs-dry` | Проверка стиля | CI-проверка без изменений |
| `make infection` | Мутационное тестирование | Проверка качества тестов |
| `make quality` | Все проверки | Полная проверка качества |

## Alternatives considered

- **Psalm** — отклонено: Psalm добавляет taint analysis, но для текущего
  проекта достаточно PHPStan. Расширение экосистемы PHPStan шире для
  Symfony/Doctrine. Можно добавить позже при необходимости security
  scanning.
- **PHPCS** (PHP_CodeSniffer) — отклонено: экосистема угасает, PHP-CS-Fixer
  полностью покрывает потребности в форматировании. PHPCS полезен для
  кастомных sniffs, но в данном проекте это не требуется.
- **Rector** — отклонено: инструмент для миграций и рефакторинга, не для
  повседневного контроля качества. Можно добавить позже при обновлении
  версий PHP/Symfony.
- **PHPStan + Psalm одновременно** — отклонено избыточно: 80% перекрытия,
  двойной расход CI-времени. PHPStan покрывает потребности проекта.

## Consequences

- Положительно: автоматический gatekeeper блокирует PR с ошибками типов,
  нарушениями стиля и слабыми тестами.
- Положительно: baseline позволяет внедрить анализ без немедленного
  исправления legacy-кода.
- Положительно: `composer quality` — единая команда для полной проверки
  перед коммитом.
- Положительный: MSI ≥ 70% гарантирует, что тесты проверяют логику, а
  не просто покрывают строки.
- Отрицательно: начальный overhead на исправление ошибок baseline.
- Отрицательно: Infection значительно замедляет CI (мутации = запуск
  тестов для каждого мутанта). Оптимизация: `--threads=N`,
  `--git-diff-filter=AM`, запуск Infection отдельным job.
- Отрицательно: повышение уровня PHPStan (5 → 8) потребует постепенных
  исправлений в коде.
