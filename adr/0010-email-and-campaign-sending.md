# ADR-0010: E-mail и сервис запуска рассылки

- **Status:** accepted
- **Date:** 2026-08-12
- **Related:** ADR-0015 (сайт и город организации), ADR-0016 (журнал
  результатов отправки писем — отдельный канал логирования поверх модели
  доставки, описанной здесь)

## Context

Рассылки отправляются организациям, отмеченным во время обзвона, или
организациям, выбранным вручную. Отправка должна идти без очередей
(RabbitMQ/Redis не вводятся), а менеджер должен видеть ход отправки письма.

## Decision

Транспорт — **SMTP через Symfony Mailer** (Mailpit/Mailhog в dev, реальный
SMTP в prod). Используется outbox-паттерн: для каждого получателя в БД
сохраняется запись «письмо к отправке» со статусом, а отдельная
worker-команда (Symfony command) выполняет фактическую отправку.

**Статусы per-письмо:** `pending → sent → {delivered | bounced}`, плюс `opened`.
- `sent` — письмо передано на SMTP;
- `delivered` / `bounced` — ответ от SMTP сразу (доставлено / технический
  отказ);
- `opened` — через tracking-pixel (невидимая 1×1 картинка с уникальным
  токеном в теле письма; при запросе на неё письмо помечается прочитанным).

Менеджер видит статус по каждому письму и общий прогресс рассылки (X из N,
процент отправленных/прочитанных).

Рассылка не привязана к одной организации: адресаты — организации из
результатов звонков и/или выбранные вручную. Письмо формируется по одному
шаблону с токенами (`{{contact_name}}`, `{{organization_name}}`) и встроенными
курсами (см. спеки `communication-templates`, `courses`).

Результаты фактической отправки дополнительно пишутся в отдельный канал журнала
`mailer` с маскированием адресов, месячными файлами и архивированием по годам —
см. ADR-0016. Модель доставки и статусы, описанные выше, этим не меняются:
журнал является наблюдательным артефактом, а правым источником о статусе письма
остаётся `campaign_recipient`. Решение о таблице записей отправки не создаётся
сохраняется: см. также ADR-0015 (справочные поля организации) — к модели
доставки отношения не имеет.

## Consequences

- Отправка работает без внешней очереди: только БД и команда-writer.
- Прогресс виден в реальном времени по записям outbox.
- Техническая доставка/отказ определяется сразу из SMTP-ответа; факт
  прочтения — по pixel.
- В dev письма попадают в Mailpit, prod-настройка (SMTP-учётные данные) — через
  переменные окружения.
